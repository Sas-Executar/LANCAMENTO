2. Group capabilities by single responsibility rather than by UI screen.
3. For each skill define name, purpose, trigger, required context, input schema, output schema, side effects and permission level.
4. Classify each skill as read-only, draft-producing, write/mutation, publish/deploy, or external-action.
5. Require explicit authorization for irreversible/external actions according to current environment policy.
6. Define deterministic errors, retries and idempotency keys for mutation skills.
7. Define audit payload: task id, actor, source, action, target, result and evidence.
8. Map which skills VERA may invoke automatically versus only after user confirmation.
9. Create tests/evals for valid input, invalid input, tool failure, duplicate retry and permission denial.
